## 1. Инженерные принципы (не обсуждаются без CEO)

1. **Данные первичны, изображения вторичны.** Всё — проекция StyleSpec. Никогда не хранить «правду» в картинке или PDF. Это ров продукта (конкурент застрял в генеративных картинках — см. разбор).
2. **Детерминизм.** Одинаковый вход → одинаковый StyleSpec. LLM-вызовы: temperature минимальная, structured output (JSON Schema), версионированные промпты. Генеративная вариативность = баг, не фича.
3. **Честность значений на уровне типа.** `confidence: user_input | estimated_from_photo | default_from_base | assumption | fit_confirmed` — обязательное поле каждого значимого значения. Значение без источника не компилируется.
4. **RAT-дисциплина: код пишется только тот, что производит артефакты для ближайшего теста.** Стоп-краны в дорожной карте — жёсткие. Фичи «на будущее» = запрещены.
5. **Скучный стек.** Ни одной технологии ради технологии. Каждый выбор — обоснование в ADR (architecture decision record, файл в репо).
6. **Себестоимость — метрика первого класса.** Логировать токены/стоимость каждой генерации с первого дня. Цель: COGS ≤ 20% чека при ручном QA, ≤ 10% без него.
7. **Справочники — это код.** KB-JSON версионируются в репо, меняются через PR с описанием причины (ошибка QA, фидбек фабрики). Петля обучения продукта — без ML-тренинга.
8. **Безопасность по умолчанию:** секреты в env, доступ к данным пользователей только через API-слой, бэкапы с первого продакшн-дня, никакого пользовательского контента в промптах логов.

## 2. Архитектура (целевая, наращивается по фазам)

```
[Клиенты: лендинг · веб-апп · админка]
        │ HTTPS/JSON
[API-слой (монолит, модульный)]
  ├── auth (email-код)
  ├── projects / packs CRUD
  ├── generation-оркестратор ──► очередь задач ──► воркеры:
  │       vision-анализ (Claude API, structured output)
  │       spec-assembly (детерминированный код + KB-JSON)
  │       svg-рендер (параметрические шаблоны)
  │       document-рендер (HTML→PDF)
  ├── billing (кредиты, «списание за успех»)
  └── notifications (email; позже TG)
[PostgreSQL: users, styles, stylespec-снапшоты(JSONB), versions, fit_comments, credits, events]
[Object storage: фото, PDF, SVG]
[KB-справочники: JSON в репо, грузятся в память]
[Наблюдаемость: structured logs, Sentry-класс ошибки, метрики генераций/стоимости]
```

**Ключевые контракты:**

- `StyleSpec` — единственная схема правды (JSON Schema в репо, версионируется `spec_version`; миграции снапшотов — твоя ответственность).
- `VisionReport` — строго типизированный выход vision-этапа (категория, элементы, пропорции, not_visible[]) — по карте «видно/не видно» из KB-04.
- Рендеры — чистые функции `StyleSpec → SVG/HTML/PDF`, без побочных состояний: это делает диффы версий и тесты тривиальными.

**Стек (ADR-0):** TypeScript + Node (Fastify/NestJS — на твой вкус, обосновать) · Next.js (лендинг + апп) · PostgreSQL (+JSONB) · BullMQ/pg-boss для очереди · Claude API (vision + structured output) · SVG-шаблоны на чистом SVG+TS · Playwright/Puppeteer для PDF · S3-совместимый сторедж · деплой: одна VPS/PaaS на старте, докеризовано с первого дня. РФ-специфика: почтовый провайдер с доставляемостью в РФ, платёжка ЮKassa/CloudPayments (фаза 2).

## 3. Дорожная карта: от сегодня до 1000 платящих

### ФАЗА 0 — «Станок» (недели 1–3) → артефакты для RAT-1/RAT-2

Цель: CLI, который из фото футболки делает полный техпак-PDF уровня приёмки.

Задачи по неделям:

- **Неделя 1:** репо, CI, ADR-каркас · KB→JSON: `size_charts_ru`, `ease_defaults`, `pom_templates/tshirt`, `tolerance_classes`, `grading_increments`, `construction_nodes` (трикотажное ядро), `materials`, `care_symbols` (источники: knowledge-base 03/04/05/06; помеченные ⚠ значения переносить с `verified:false`) · JSON Schema StyleSpec · vision-промпт v1 со structured output + голден-тесты на 5 эталонных фото.
- **Неделя 2:** spec-assembly: POM-движок (якорь размера → сетка+ease → пропорции → клэмп → допуски → градация) · construction-движок (дефолты категории + visible_elements + machine-park check) · BOM-движок (+предварительный расход) · labels-движок (символы ухода, SKU-матрица) · **прототип параметрического SVG «футболка» (перед/спинка)** — чекпоинт рва: если за неделю флэт не выглядит профессионально → fallback на заготовки с контрольными точками (решение с CEO).
- **Неделя 3:** document-рендер: HTML→PDF, все страницы, легенда статусов на первой, экспорт по ролям · CLI `generate --photos --answers.json → pack.pdf` · прогон 3 реальных референсов (худи, футболка, лонгслив) → ручная доводка → **3 артефакта для похода по фабрикам**.

**DoD фазы 0:** 10 эталонных фото проходят пайплайн без падений; повторный прогон → идентичный StyleSpec; себестоимость генерации посчитана; 3 PDF отданы CEO для RAT-1.

### 🛑 СТОП-КРАН 1: результат RAT-1 (приёмка фабриками)

Дальше — только после «≥6 из 10 фабрик берут в работу». Провал → пересборка ценности (см. PRD §9), не наращивание кода. Пока идёт тест (3–4 недели) — разрешённая работа: голден-тесты, справочники, concierge-исполнение заказов RAT-2 через CLI, лендинг с waitlist.

### ФАЗА 1 — «Витрина + станок в аренду» (месяцы 2–3) → v0.2 self-serve

- Лендинг (бриф ux/04) + waitlist-механика + аналитика (события: заявки, роли, utm).
- Веб-апп: auth email-код · дашборд · мастер (3 шага, категорийный гейт) · генерация (очередь, статусы, повтор бесплатно) · Workspace: Обзор + Замеры + Чертёж (live-связь данные→SVG) · экспорт PDF полный.
- Биллинг: кредиты, «списание за успех», ЮKassa; тhighlights Founding-100.
- Concierge-админка: очередь заказов, QA-чек с чек-листом технолога, редактор справочников, лиды.
- Наблюдаемость: Sentry, дашборд генераций (успех/ошибки/стоимость/время).
  **DoD:** незнакомый основатель проходит фото→PDF за ≤7 минут без помощи; платёж работает; QA-петля админки живая. Цель конца фазы: **первые 20–50 платящих** (из waitlist-волн).

### ФАЗА 2 — «Глубина» (месяцы 4–6) → v0.3

- Workspace: Материалы (BOM+colorways) · Конструкция (коды/SPI/машины, альтернативные узлы) · Ярлыки/SKU · Версии+примерки · Библиотека бренда · экспорт по ролям · послойный SVG.
- Категории: свитшот, худи, лонгслив (шаблоны SVG + KB-дефолты).
- Мост THE MONO: «отправить на просчёт» (интеграция или ручной релей — по готовности биржи).
- SEO-кластер: 12 страниц гайдов из knowledge-base (шаблон статьи + CTA-виджет).
- Улучшение точности: таксономия ошибок из QA/примерок → правки промптов и справочников; доля генераций без ручных правок QA — ключевая внутренняя метрика.
  **DoD:** ≥4 категории; NPS-опрос в продукте; повторное использование ≥40%; цель: **150–300 платящих**, QA-время на пак ↓ вдвое.

### ФАЗА 3 — «Масштаб» (месяцы 7–12) → 1000 платящих

- **Надёжность:** SLO: аптайм 99.5%, p95 генерации ≤ 5 мин, ошибка генерации ≤ 2%; ретраи и graceful degradation (vision упал → очередь с уведомлением); статус-страница.
- **Снижение ручного QA:** автопроверки StyleSpec (валидаторы диапазонов, кросс-проверки POM↔категория), выборочное QA вместо тотального (сначала новые категории/низкий confidence); цель — QA ≤ 10% паков.
- **Себестоимость:** кэш vision-результатов, батчинг, дешёвые модели на простых этапах; COGS ≤ 10% чека.
- **Поддержка 1000 пользователей:** in-app хелп + база знаний · тикеты (почта→трекер) с SLA 24ч · админ-инструменты: просмотр пака глазами пользователя (с согласия), ручной перезапуск, возврат кредитов в 1 клик · алерты аномалий (всплеск ошибок категории) · еженедельный дайджест CEO: метрики, топ-ошибки, топ-запросы.
- **Данные:** бэкапы (ежедневно, restore-тест ежемесячно), экспорт данных пользователя, удаление по запросу, 152-ФЗ-гигиена (персональные данные в РФ-контуре — проработать с CEO юрчасть).
- Селлер-режим С2 (пакетная генерация) — по сигналам из ролей waitlist и юзеров.
  **DoD:** 1000 платящих обслуживаются без найма людей в саппорт первой линии; unit-экономика сходится (LTV/CAC — считает CEO, ты даёшь данные).

## 4. Правила нашей совместной работы (CEO ↔ CTO)

1. **Задачи приходят ссылками на спеки**, не пересказом. Расхождение спеки и реальности → ты предлагаешь правку спеки, а не молча решаешь.
2. **Каждая фича — вертикальный срез** (данные → API → UI → тест), не слоями.
3. **Definition of Done всегда:** код + тест + прогон голден-сета + обновлённый ADR/док + строка в CHANGELOG.
4. **Еженедельный отчёт** (коротко): сделано / метрики (генерации, успех, стоимость, время) / риски / решения, которые нужны от CEO.
5. **Ты обязан спорить.** Если требование дорого/рискованно/есть путь дешевле — говоришь до, а не после. Особенно про стоп-краны: строить дальше без результата теста нельзя, даже если CEO в азарте.
6. **Не трогать без явного решения CEO:** прайсинг, публичные обещания (лендинг-тексты), удаление данных пользователей, обход стоп-кранов, смена стека.
7. **Голден-сет — священен:** 10→50 эталонных фото с ожидаемыми StyleSpec; каждый PR прогоняет их; деградация точности блокирует мерж.

## 4.a Работа с готовым дизайн-макетом

Дизайн-макеты продукта готовы (источник передаст CEO — экспорт из Claude Design / скриншоты / код-прототипы). Правила имплементации:

1. **Макет — источник композиции, спеки — источник поведения.** Расхождение макета с `ux/02-screens-spec.md` (состояния, edge cases, флоу) → поведение берётся из спеки, визуал из макета; конфликт — вопрос CEO, не молчаливый выбор.
2. **Токены из `design_handoff_seamsterly/README.md` («Дизайн-токены») — единственная правда о цветах/шрифтах/радиусах/тенях/анимациях.** _(Изменено решением CEO 2026-08-25, D1 в `DEV-PLAN.md` §2: раньше здесь стоял `UI-SPEC-app.md` §1 — его блок токенов отменён и помечен как история.)_ Реализовать как design tokens (CSS-переменные/tailwind-конфиг) один раз в `packages/ui/tokens`; никаких хардкод-значений в компонентах. Фиделити хендоффа — high: нестандартные значения (13px, 27px, 9.7px) намеренные, к сетке 4/8px не округлять.
3. **Пиксель-перфект не самоцель:** совпадение сеток, иерархии и паттернов обязательно; субпиксельные отличия не блокируют.
4. Каждый экран реализуется со ВСЕМИ состояниями из спеки (empty/loading/error/success), даже если в макете нарисован только happy path.
5. Компонентная библиотека сначала (кнопки, чипы статусов, таблицы, карточки) → потом экраны из компонентов. Чип статуса уверенности — один компонент на весь продукт.
6. После вёрстки каждого экрана — самопроверка по стиль-тесту `UI-SPEC-app.md` §8 + скриншот в отчёт CEO.

## 5. Риски инженерные (твой личный RAT)

| Риск                                             | Митигация                                                                                                                            |
| ------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------ |
| Параметрический SVG не даёт профессиональный вид | чекпоинт недели 2; fallback: заготовки художника с контрольными точками; крайний случай — гибрид с genAI-подложкой ТОЛЬКО для превью |
| Vision нестабилен на реальных фото пользователей | голден-сет + подсказки качества в мастере + graceful «оценка по фото» со сниженным confidence, не падение                            |
| Стоимость inference съедает маржу                | лог себестоимости с 1-го дня; бюджет на пак; алерт при превышении                                                                    |
| KB-значения с `verified:false` дают брак         | приоритет верификации по частоте использования; каждая правка из QA — коммит в KB                                                    |
| Один человек-команда (ты) = бас-фактор           | вся правда в репо: ADR, спеки, runbook деплоя/рестора — новый инстанс тебя поднимает контекст за час                                 |
