**Эмоциональная кривая:** тревога (1–2) → скепсис (3) → доверие растёт (4) → пик-восторг (5) → уверенное владение (6–7) → спокойствие (8–10). Дизайн-вывод: до этапа 5 — минимализм и забота (ничего лишнего, всё объяснено); после — плотность и контроль (пользователь «повзрослел»).

**CJM С2 (селлер) — отличия одной строкой на этап:** триггер — трендовое окно, не запрос фабрики · ищет скорость, не понятность · мастер должен уметь «5 моделей пачкой» (roadmap) · Aha = «ТЗ за час» · правки минимальны · экспорт сразу в мессенджер фабрике · примерку часто пропускает (риск — напомнить о возвратах) · retention через частоту, не через глубину.

# Часть 2. Пользовательские флоу

Формат: шаги → [ветки] → состояния. Каждый флоу — сценарий для прототипа.

## F1. Первый техпак (мастер) — критический флоу продукта

1. Dashboard (empty) → CTA «Создать техпак» → **Шаг 1: Фото.** Дропзона (1–6 файлов, jpg/png/webp/heic ≤15 МБ).
   - [загружено] превью-сетка, ре-порядок, «главное фото» первым
   - [файл битый/тяжёлый] инлайн-ошибка на файле, остальные живут
   - [фото сомнительное] (тёмное/мелкое): мягкое предупреждение «точность будет ниже — можно продолжить»
2. **Шаг 2: 5 вопросов** (каждый — карточка с «почему спрашиваем»):
   a. Категория — автоопределение по фото, подтверждение чипами («Похоже, худи — верно?»).
   - [вне MVP-категорий: пальто/бельё/сложное] → честный гейт: «Эту категорию пока не делаем хорошо — оставьте почту, позовём» + waitlist категории. НЕ генерируем плохое. |трасса: слабость №18|
   b. Базовый размер + рост (селекторы RU/INT с двойной шкалой; дефолт M/46·170) |№1|
   c. Посадка — 4 карточки с силуэтами (прилегающая/обычная/свободная/oversize)
   d. Материал — автоопределение (трикотаж/ткань) + подтверждение; опционально плотность
   e. Размерный ряд (чипы 42–52 / XS–XL) + тираж (число; только для подсказок)
   - Свёрнутый блок «Повысить точность»: фото с А4/картой в кадре; один ручной замер (одно поле: «длина по спинке, см»)
3. Кнопка «Собрать техпак» → F2.

- [выход в любом шаге] автосохранение черновика; на дашборде карточка «черновик — продолжить».

## F2. Генерация

1. Полноэкранный прогресс, реальные этапы: «Анализируем фото → Строим чертёж → Считаем замеры → Подбираем материалы → Собираем документ», общий ETA.
2. [успех] → переход-раскрытие: документ «собирается» на экране (обложка → чертёж → таблица) = спроектированный Aha. Сразу под ним сводка: «✅ 34 значения рассчитаны · ⚠️ 6 — подтвердить по образцу» |№4, №5|
3. [частичный успех] (например, спинка не распозналась): документ открывается, проблемные зоны помечены «нужно ваше фото/подтверждение», генерация не блокируется целиком.
4. [ошибка] человеческий текст причины + «Повторить бесплатно» (кредит не списан |№20|) + «Написать нам» (виден SLA ответа).
5. v0.1 (concierge): статус «проверяется технологом» между генерацией и выдачей — бейдж «проверено человеком» на документе |№19|.

## F3. Правка замера (ядро доверия)

1. Экран «Замеры» → клик по значению → инлайн-редактирование.
2. Ввод → валидация диапазона категории [вне диапазона: жёлтое предупреждение «необычно для худи — уверены?», не блокируем].
3. Сохранение: чертёж анимированно перестраивается ≤1 сек |№11, №12|; статус значения → «указано вами»; зависимые значения пересчитываются с подсветкой «изменилось из-за вашей правки».
4. Градация ряда пересчитывается [Pro: можно править приращения; кнопка «сбросить к рассчитанным»] |№3|.
5. Undo/redo; история правок в версии.

## F4. Работа с чертежом

1. Экран «Чертёж»: вкладки перед/спинка, зум/пан, слои (контур/швы/строчки/фурнитура/выноски).
2. Клик по элементу чертежа → подсветка связанной строки (узла/материала) в правой панели; и наоборот — ховер строки подсвечивает зону на чертеже.
3. Правка геометрии — только через данные (замер/узел); тултип на «почему нельзя рисовать»: «чертёж строится из данных — измените замер или узел, и он перестроится точно».
4. [элемент распознан неверно] «На фото не так» → мини-диалог: выбрать правильный вариант элемента (тип кармана/горловины) → перегенерация только этого узла.

## F5. Материалы (BOM)

1. Таблица по группам; каждая строка со статусом уверенности |№4|.
2. Правка состава/плотности: селекторы из справочника [ручной ввод — Pro].
3. Замена материала → пересчёт зависимых узлов (трикотаж→ткань меняет швы — предупреждение с列 списком затронутого).
4. «Добавить из библиотеки бренда» [пусто → «сохраните материал, чтобы переиспользовать»].
5. Расход: показан с пометкой «предварительно, уточняется фабрикой по раскладке» |№14|; тултип «почему предварительно».
6. Colorway-переключатель: копия BOM на цвет, отличия подсвечены |№15|.

## F6. Конструкция + machine-park check

1. Список узлов по зонам; каждый узел: простое описание [Pro: код шва ГОСТ=ISO, SPI, машина] |№9|.
2. Узел со спецоборудованием → флаг «⚙ нужна спецмашина (например, распошивалка)» + кнопка «Заменить на узел под базовый цех» → диф-превью двух вариантов → замена одним кликом |№10|.
3. Невидимые с фото узлы → статус «предположение» + собранный блок «Уточнить у фабрики» (автосписок всех допущений) |№8|.
4. Правка узла → обновление чертежа (выноски) и техпоследовательности.

## F7. Ярлыки и маркировка

1. Автособранные макеты: составник (символы ухода из материала — редактируемые кликом по символу), размерник, навесной ярлык.
2. Юрданные бренда [не заполнены → инлайн-форма «для ярлыка нужны реквизиты» с сохранением в профиль].
3. SKU-матрица (артикул × цвет × размер), GTIN-плейсхолдеры, подсказка «что такое Честный знак» |№17|.

## F8. Экспорт и передача

1. Экран «Экспорт»: превью PDF → выбор: полный PDF · по ролям (чипы: технолог/закройщик/ОТК/снабжение) · SVG послойный |№16|.
2. [есть допущения] мягкий гейт: «В документе 6 неподтверждённых значений — они помечены для фабрики. Экспортировать?» (не блокируем — честность, не запрет).
3. Сопроводительный текст фабрике (копируемый шаблон: «Прошу просчитать по документации…»).
4. Кнопка «Отправить на просчёт фабрикам THE MONO» → мини-флоу: подтверждение состава заявки → статус «на просчёте» на карточке проекта [THE MONO недоступен → «скоро», waitlist] |мост экосистемы|.
5. Лекала: карточка-заглушка «Лекала делаются конструктором по этому техпаку» + «передать конструктору» (share-ссылка) |№7|.

## F9. Цикл образца (примерки и версии)

1. Пуш/письмо «Получили образец? Внесите примерку» (по сроку из просчёта).
2. Экран «Версии» → «+ Примерка образца» → таблица: точка · по спеке · факт (ввод) · дельта (авто) · в допуске? (авто-бейдж) · комментарий; фото образца.
3. «Применить правки» → новая версия документа (v2), изменённые значения помечены «по примерке №1» |№13|.
4. Экспорт версии → фабрике; история версий — таймлайн со сравнением [Pro: диф двух версий].

## F10. Колорвеи

1. «+ Добавить цвет» на обложке → выбор из фото / Pantone-пикер.
2. Копируется BOM с заменой цветозависимых позиций; SKU-матрица расширяется; чертёж — превью в цвете [опционально].

## F11. Тариф и кредиты

1. Баланс на видном месте; списание — только успешная генерация; повтор — бесплатно |№20|.
2. [кредиты кончились в мастере] мягкий пейволл до шага генерации (не после заполнения!): тарифы + «заказчикам THE MONO — бесплатно» с проверкой связки.
3. История списаний с привязкой к техпакам.

## F12. Pro-режим (сквозной)

1. Переключатель в шапке Workspace; состояние запоминается.
2. ВКЛ: коды швов/SPI/машины, приращения градации, PON-коды, ручные вводы вместо селекторов, техпоследовательность полностью.
3. ВЫКЛ: те же данные, свёрнутая подача. Никаких отдельных «Pro-экранов» — только плотность.
