# SpecForm — UI/UX-спецификация приложения (для проектирования в Claude Design)
> v1.0 · 2026-07-16 · основа: TECH-REQUIREMENTS-PIPELINE.md (архитектура StyleSpec) + knowledge-base 01–07
> Имя «SpecForm» — плейсхолдер. Аудитория интерфейса №1 — основатель бренда БЕЗ технического бэкграунда; режим Pro — для конструкторов.

## 0. Главный принцип интерфейса

**Продукт = живой документ, а не генератор картинок.** Всё в UI подчинено трём правилам:
1. **Единый источник данных:** правка любого поля (замер, узел, материал) немедленно отражается в чертеже, таблицах и превью PDF. Никаких «перегенерируйте, чтобы увидеть».
2. **Честность значений:** каждое значение несёт видимый статус уверенности. 4 статуса: ✅ `указано вами` · 📷 `оценка по фото` · 📚 `типовое значение` · ⚠️ `предположение — подтвердить по образцу`. Визуально: тонкая цветная точка/чип у значения + фильтр «показать все предположения».
3. **Прогрессивное раскрытие:** новичок видит простые слова и мастер-флоу; профи разворачивает плотность (ГОСТ-коды, SPI, допуски) переключателем «Pro-режим». Данные одни — глубина подачи разная.

## 1. Дизайн-система (стиль зафиксирован: «Daxa» — светлый инженерный дашборд)

**Референс:** светлый воздушный дашборд — белые карточки на светло-сером, чернильный текст, один свежий зелёный акцент, крупные цифры как объекты, правая AI-панель. SpecForm визуально самостоятелен: НЕ наследует кобальт/лайм/конденсированный капс THE MONO — родство только в светлой карточной основе и скруглениях.

**Токены:**
- Фон приложения: светло-серый `#F2F2F0` (маркетинг может чуть теплее). Карточки: белые `#FFFFFF`, radius 16–20px, мягкая тень низкой интенсивности, без обводок либо `#E8E8E5`.
- Текст: чернильный `#161616`; вторичный `#8A8A85`. Шрифт: гуманистический гротеск (Golos Text / Inter / аналог из референса), заголовки обычным начертанием 600–700, БЕЗ капса.
- **Акцент — один: зелёный `#3DE06E` (яркий, из референса).** Только заливки чипов/прогрессов/индикаторов с тёмным текстом поверх; **никогда — цветом текста на белом** (контраст). Для текстовых статусов — тёмно-зелёный `#0D6E5F`.
- **Семантика цвета — строгая.** Зелёный зарезервирован под «подтверждено/принято». Статусы уверенности значений: ✅ подтверждено `#0D6E5F` (чип с зелёной заливкой) · 📷 оценка по фото `#4A6CF7` (сдержанный синий) · 📚 типовое значение `#8A8A85` (серый) · ⚠️ предположение `#B3261E` (красный, единственное применение красного кроме ошибок). Цвет никогда не используется декоративно — если элемент цветной, это значит что-то одно и то же везде.
- **Крупные цифры как объекты** (паттерн референса: 97,22 / 71,74): для сводок — «6 значений подтвердить», «допуск ±1,0», прогресс генерации. Табличные цифры (tabular-nums) везде, где числа в колонках.
- Таблицы: 14–15px, зебра или тонкие разделители, липкие заголовки, плотность выше маркетинговой.
- Чертёж (SVG-флэт): всегда на чистом белом поле карточки, ч/б линии — герой экрана; никакой подложки, паттернов и теней под чертежом.

**Три жёстких правила стиля (из критики референса):**
1. **Глассморфизм/блюр-карточки — только для маркетинговых поверхностей и инсайт-баннеров.** В рабочих экранах (таблицы, чертёж, BOM) — запрещён: полупрозрачность подрывает доверие к значениям.
2. **Никаких декоративных графиков.** Референс — аналитический дашборд, но SpecForm — документ: спарклайны и диаграммы появляются только там, где их просят данные (прогресс генерации, дельты примерок). Пустая красота запрещена.
3. **AI-панель справа** (паттерн референса) используется как контекстная панель Workspace и чат генерации — это наше легитимное наследование.

## 2. Карта продукта (3 поверхности)

1. **Маркетинг** — лендинг (готов отдельно), страницы тарифов, база знаний.
2. **Приложение (web, desktop-first 1440, работает от 1024)** — этот документ.
3. **Concierge-админка (v0.1)** — внутренняя: очередь заказов, ручная проверка QA, правка справочников. Проектируется утилитарно, без дизайна (таблицы), в спеку не входит.

## 3. Информационная архитектура приложения

```
Auth → Projects (дашборд)
         └── New Tech Pack (мастер: 3 шага)
         └── Tech Pack Workspace (рабочее пространство документа)
               ├── Обзор (cover)
               ├── Чертёж (flats)
               ├── Замеры (POM + градация)
               ├── Материалы (BOM)
               ├── Конструкция (узлы + техпоследовательность)
               ├── Ярлыки и маркировка
               ├── Версии и примерки (fit comments)
               └── Экспорт
         └── Библиотека бренда (материалы, размерные сетки, юрданные)
         └── Настройки / Тариф и кредиты
```

## 4. Экраны

### 4.1. Auth
Email + код (без паролей). Однострочный экран, лого, одно поле. Состояния: ввод email → ввод кода → ошибка кода → успех.

### 4.2. Projects — дашборд
- Сетка карточек техпаков: превью флэта, название, категория, статус (`черновик · генерация · готов · отправлен на просчёт`), дата, счётчик версий.
- Пустое состояние (важно! первый экран новичка): большая карточка «Создай первый техпак из фото» + мини-иллюстрация процесса + кнопка. Ни одного пустого экрана без действия.
- CTA «+ Новый техпак» — постоянно в шапке.
- Фильтр по статусу/категории. Поиск.

### 4.3. New Tech Pack — мастер (3 шага, самый важный флоу)
Одностраничный степпер с прогрессом, всегда видно «шаг X из 3».

**Шаг 1 — Фото.** Дропзона до 6 изображений (референс, скрин карточки, эскиз); превью с удалением; подсказка «чем ровнее ракурс — тем точнее чертёж». Валидация: не менее 1.
**Шаг 2 — 5 вопросов** (каждый с «почему мы спрашиваем» в одну строку):
1. Категория (авто-угадана по фото, показана как подтверждение: «Похоже, это худи — верно?» чипы-варианты)
2. Базовый размер + рост (`RU 46 / M · 170` — селекторы с двойной шкалой RU/INT)
3. Посадка (4 карточки-силуэта с картинками: прилегающая · обычная · свободная · oversize)
4. Материал (трикотаж/ткань — авто-угадан, подтверждение; опционально плотность)
5. Размерный ряд + тираж (чипы 42–52 / XS–XL; тираж числом — влияет только на подсказки)
Опционально (свёрнуто): «повысить точность» — фото с предметом-референсом (А4/карта), один ручной замер.
**Шаг 3 — Генерация.** Полноэкранный прогресс с реальными этапами («Анализируем фото → Строим чертёж → Считаем замеры → Собираем материалы → Формируем документ»), ~общее время, факт-карточки о продукте пока ждёт. Ошибка: понятный текст + «повторить бесплатно». Успех → Workspace.

### 4.4. Tech Pack Workspace — ядро продукта
Макет: слева вертикальные табы-разделы (7 шт, как страницы документа), центр — контент раздела, справа — контекстная панель (детали выбранного элемента). Сверху: название + статус + версия, переключатель «Pro-режим», кнопки [Экспорт] [Отправить на просчёт → THE MONO].

**Обзор (cover):** карточка стиля (название, артикул, категория, сезон, размерный ряд, базовый размер), референс-фото, миниатюра флэта, сводка предположений: «⚠️ 6 значений требуют подтверждения по образцу — посмотреть».

**Чертёж (flats):** большой SVG-вьювер (перед/спинка табами, зум, пан). Слои-переключатели: контур · швы · строчки · фурнитура · выноски. Клик по элементу чертежа → подсветка соответствующей строки конструкции в правой панели (и наоборот). Правка геометрии — только через данные (замеры/узлы); прямого «рисования» нет — это фича, а не ограничение, объяснена тултипом.

**Замеры (POM):** таблица: код · точка (рус + подсказка «как мерить» с мини-диаграммой по ховеру) · значение базового размера · допуск (± , перекрываемый per-строка) · статус уверенности · [колонки размеров ряда — автоградация]. Редактирование инлайн; правка значения → live-обновление пропорций флэта. Кнопки: «пересчитать градацию», «сбросить к рассчитанным». Pro-режим показывает приращения градации. Диаграмма замеров (флэт со стрелками) — сплит-вью справа.

**Материалы (BOM):** таблица по группам (полотно/фурнитура/нитки/прокладки/упаковка): позиция · описание · состав/плотность · цвет (Pantone-чип) · расход (с пометкой «предварительно, уточняется фабрикой») · статус. Добавление из библиотеки бренда или каталога-справочника. Colorway-переключатель сверху (BOM на каждый цвет).

**Конструкция:** список узлов по зонам (горловина, плечи/бока, низ, карманы, застёжка): узел · описание простыми словами · Pro: код шва/стежка (ГОСТ=ISO) · SPI · машина. Флаг «⚙ требует спецоборудования» с кнопкой «заменить на альтернативу под базовый цех». Ниже — техпоследовательность (нумерованная таблица операций, Pro-режим). Каждый узел связан с выноской на чертеже.

**Ярлыки и маркировка:** макеты составника (символы ухода — авто по материалу, редактируемые), размерника, навесного ярлыка; поля юрданных из профиля бренда; SKU-матрица (артикул × цвет × размер) с GTIN-плейсхолдерами и пояснением про «Честный знак».

**Версии и примерки:** таймлайн версий (v1 исходная → v2 после образца …). Внутри версии — fit-комментарии: таблица «точка · по спеке · факт образца · дельта · в допуске? · действие»; фото образца; кнопка «применить правки в новую версию». Это язык sample rounds, поданный простыми словами («Примерка образца №1»).

**Экспорт:** карточки форматов: PDF полный · PDF по ролям (технолог / закройщик / ОТК / снабжение — мультивыбор) · SVG послойный · «Отправить на просчёт фабрикам THE MONO» (мост в экосистему, выделен лаймом). Превью PDF. История экспортов.

### 4.5. Библиотека бренда
Материалы (переиспользуемые между техпаками), размерная сетка бренда (перекрывает ГОСТ-дефолты), юрданные для ярлыков, логотип. Пустые состояния с объяснением пользы.

### 4.6. Тариф и кредиты
Баланс техпаков, история списаний (только успешные генерации — прописано явно), тарифы, промо ранних. Для клиентов THE MONO — бейдж «безлимит по заказам платформы».

## 5. Сквозные паттерны

- **Статус уверенности** — единый компонент (точка+чип+тултип «откуда это значение»), используется в замерах, BOM, конструкции. Глобальный фильтр «показать предположения» в шапке Workspace.
- **Терминовые тултипы** — первый показ термина (POM, BOM, допуск, градация…) всегда с подсказкой; словарь — в базе знаний.
- **Автосохранение** всего; индикатор «сохранено» у названия. Undo/redo в таблицах.
- **Скелетоны** при загрузке; **пустые состояния** всегда с действием; ошибки — человеческим языком с кнопкой решения.
- **Уведомления**: генерация завершена, просчёты пришли (из THE MONO), напоминание «подтвердите замеры по образцу».

## 6. Ключевые флоу (для прототипирования в первую очередь)

1. **Happy path:** Auth → пустой дашборд → мастер (фото→вопросы→генерация) → Workspace → Экспорт PDF. Цель: ≤ 7 минут до первого документа. Aha-момент — первый показ готового флэта с таблицей замеров: спроектировать как «вау-раскрытие» (анимация сборки документа).
2. **Правка замера:** таблица POM → изменение значения → live-обновление флэта → статус меняется на «указано вами».
3. **Цикл образца:** экспорт → (офлайн отшив) → «Примерка образца» → ввод фактов → новая версия.
4. **Мост в THE MONO:** «Отправить на просчёт» → выбор фабрик/условий → статус «на просчёте» на карточке проекта.

## 8. Критерии приёмки дизайна
- Новичок доходит от фото до PDF без единого незнакомого слова без подсказки.
- Любое значение отвечает на «откуда это число» в один ховер.
- Правка замера видимо меняет чертёж ≤ 1 сек (в прототипе — анимация-имитация).
- Pro-режим не добавляет экранов — только раскрывает плотность существующих.
- Ни одного пустого состояния без действия; ни одного статуса без следующего шага.
- **Стиль-тест (5 вопросов) на каждом макете:** герой экрана — документ? таблица на 18 строк не разваливается? текст 14px проходит контраст AA? каждый цвет несёт одну семантику? экран не спутать с THE MONO, но родство видно?
- Зелёный встречается на экране только в значении «подтверждено/принято/готово»; блюр — только вне рабочих данных.
