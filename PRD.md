# PRD — Seamsterly (рабочее имя)

> v1.0 · 2026-07-16 · владелец: Данил · статус: до валидации RAT-1
> Связанные документы: `TECH-REQUIREMENTS-PIPELINE.md` (архитектура) · `UI-SPEC-app.md` (стиль/принципы UI) · `ux/00–03` (CJM, флоу, экраны, лендинг) · `knowledge-base/` (доменная база) · `2026-07-16_*market-research-result.html` (рынок и сегменты)

## 1. Суть продукта (one-liner)

AI-сервис, который превращает фото вещи в производственный техпак, принимаемый швейной фабрикой: технический эскиз, таблица замеров с допусками и градацией, материалы, узлы обработки на языке технолога. Час вместо двух недель у фрилансера. Самостоятельный продукт и точка входа в экосистему THE MONO.

## 2. Проблема и для кого

**С1 (главный сегмент): основатель малого бренда без технического бэкграунда.** Фабрика запрашивает «КД и лекала» — слов он не знает; фрилансер стоит 3–10 тыс. ₽/модель и 1–2 недели; цена ошибки — брак партии на 150–300 тыс. ₽ собственных денег. Критерии успеха (по убыванию): фабрика отшила правильно с первого раза → не нужно ничему учиться → цена → скорость.
**С2 (fast-follow): селлер маркетплейсов, копирующий тренды.** Трендовое окно 4–6 недель; критерии: скорость (≤1 час) → цена за модель (≤1–2 тыс. ₽ при 10–20 моделях/мес) → точность копии. Обслуживается тем же пайплайном в «экспресс-режиме» после стабилизации точности.
**Не сегменты сейчас:** конструкторы (Pro-режим — приятный бонус, не GTM), фабрики (бесплатный контур приёмки через THE MONO), тендеры (юр. блокер), enterprise.

## 3. Почему мы выиграем (ядро дифференциации)

Конкуренты генерируют **изображения** техпаков (gpt-image-2 → трассировка) — красиво, нередактируемо, невоспроизводимо, «доработайте сами». Мы генерируем **структурированные данные изделия (StyleSpec)**, из которых документ рендерится: правка замера обновляет чертёж; каждое значение несёт статус уверенности; узлы проверены под парк машин реального цеха; допуски и градация — автоматом. Полная трассировка 21 слабости конкурента → наши решения: `ux/00-INDEX.md`.

## 4. Цели и метрики

**North Star: доля техпаков, принятых фабрикой в работу без возврата на доработку.** Цель v1: ≥60% (kill-критерий RAT-1: ≤2 из 7 фабрик → пивот архитектуры ценности).

| Метрика                                                    | Цель                          |
| ---------------------------------------------------------- | ----------------------------- |
| Время до Aha (фото → готовый документ на экране)           | ≤ 7 минут                     |
| Завершение мастера                                         | ≥ 85% начавших                |
| Воспроизводимость (одинаковый вход → одинаковый StyleSpec) | 100%                          |
| Итерации отшива пробника по нашему техпаку                 | ≤ 2 (паритет с конструктором) |
| Маржа при чеке 3–5 тыс. ₽ (с учётом QA-слоя)               | ≥ 50%                         |
| Повторное использование ≤60 дней (С1)                      | ≥ 40%                         |
| Конверсия лендинга в waitlist                              | ≥ 8–10% целевого трафика      |

**Не-цели v1:** генерация лекал; 3D-рендеры; категории вне трикотажной базы; международные рынки; API.

## 5. Скоуп по релизам

### v0.1 — Concierge (внутренний инструмент; недели 1–3 сборки в Claude Code)

P0: справочники из KB (JSON) · Spec Assembly Engine (CLI: фото+анкета → StyleSpec) · SVG-рендер флэта «футболка» · Document Renderer (HTML→PDF, все страницы, легенда статусов на первой) · ручной QA-чек по чек-листу технолога.
Выход: 3 техпака для артефакт-теста фабрик (RAT-1) + исполнение concierge-заказов (RAT-2).
**Стоп-кран: дальше v0.1 не идём до результата RAT-1.**

### v0.2 — Self-serve web (после прохождения RAT-1)

P0: Auth · Dashboard · Мастер (F1, категорийный гейт) · Генерация (F2) · Workspace: Обзор, Чертёж, Замеры (F3–F4) · Экспорт PDF полный (F8) · кредиты «за успех» (F11).
P1: BOM (F5) · Конструкция с machine-park check (F6) · экспорт по ролям · категории лонгслив/свитшот/худи.
P2: Pro-режим (F12) · послойный SVG.

### v0.3 — Глубина и экосистема

P1: Ярлыки/SKU (F7) · Версии и примерки (F9) · Библиотека бренда · «На просчёт в THE MONO» (мост).
P2: колорвеи (F10) · диф версий · DXF-passthrough · «проверено технологом» как платная услуга · **интеграция Makemelook (собственный виджет виртуальной примерки)** как модуль «примерка/карточки товара» — с дифференциаторами, которых нет у конкурента: связка размер×типаж через якорную логику StyleSpec + фиксированный персонаж на коллекцию + ясные права. Не раньше прохождения RAT-1 и стабилизации ядра.

## 6. Функциональные требования (сводно; детально — ux/01, ux/02)

| Модуль      | Требование-суть                                                                                                                           | Приёмка                                                   |
| ----------- | ----------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------- |
| Мастер      | 5 вопросов с объяснениями; якорь размера от пользователя; гейт категорий вне MVP; черновики                                               | новичок проходит без внешней помощи; ≥85% завершение      |
| Генерация   | этапный прогресс; кредит только за успех; бесплатный повтор; (v0.1) стадия QA-технолога                                                   | ошибка всегда с причиной и действием                      |

| BOM         | по colorway; статусы; предварительный расход с пометкой; библиотека бренда                                                                | замена материала показывает каскад затронутых узлов       |

| Ярлыки      | составник/размерник/навесной; символы ухода из материала; SKU-матрица с GTIN-плейсхолдерами                                               | состав ярлыка = состав BOM (один источник)                |
| Версии      | снапшоты; примерки (спека/факт/дельта/в допуске); новая версия из правок                                                                  | экспорт любой версии                                      |
| Экспорт     | PDF полный и по ролям; легенда статусов на стр.1; шаблон письма фабрике; заглушка лекал с share конструктору                              | мягкий гейт при наличии ⚠ (предупреждение, не запрет)     |
| Тариф       | списание за успех; история; связка THE MONO=бесплатно                                                                                     | пейволл только до заполнения анкеты                       |

## 7. Нефункциональные требования

Воспроизводимость генерации · RU-язык (термины по словарю `ux/00`) · полный пакет ≤5 мин (v0.1 асинхронно) · себестоимость на техпак считается с 1-го дня · доступность WCAG AA · desktop-first 1440, рабочий диапазон от 1024.

## 8. Зависимости и допущения

Claude API (vision + structured output) · справочники KB (gaps: таблицы ГОСТ 31396/399, схемы приращений — закрыть парсингом PDF) · пул фабрик THE MONO для петли приёмки (запуск биржи — внешний риск: GTM продукта не должен стоять только на нём) · юрлицо/платежи для продаж.

## 9. Риски и валидационные ворота (из RAT-плана)

A1 приёмка фабриками (артефакт-тест, 3–4 нед.) → A4 готовность платить (concierge, параллельно) → A3 точность (отшив пробников) → A6 автономный канал (лендинг+трафик). Полные kill-критерии — в рыночном отчёте, раздел 5. **Правило: код пишется только тот, что производит артефакты для этих тестов.**

## 10. Открытые вопросы

Имя и домен (Seamsterly занят) · параметрика SVG: своя геометрия vs заготовки с контрольными точками (решает прототип недели 1–2) · лид-магнит автоответа waitlist (пример PDF vs чек-лист) · цена и упаковка тарифов (после A4/A5).
