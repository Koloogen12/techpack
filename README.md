# Seamster

Фото изделия → **StyleSpec** (структурированные данные изделия) → производственный техпак, который фабрика РФ принимает в работу. Каждое значение несёт статус уверенности.

> Фото изделия → StyleSpec → производственный техпак для фабрики РФ.

## Зачем это существует

Основатель малого бренда без технического бэкграунда получает от фабрики запрос «пришлите КД и лекала» и не знает этих слов. Фрилансер-конструктор берёт 3–10 тыс. ₽ и 1–2 недели на модель; цена ошибки — брак партии на 150–300 тыс. ₽ собственных денег.

Конкуренты генерируют **изображения** техпаков и говорят «доработайте сами». Мы генерируем **данные**, из которых документ рендерится: правка замера обновляет чертёж, узлы проверены под парк машин реального цеха, допуски и градация считаются автоматом.

**North Star:** доля техпаков, принятых фабрикой в работу без возврата на доработку.

## Три принципа, которые определяют весь код

1. **Данные первичны, изображения вторичны.** Всё — проекция StyleSpec. Правда никогда не живёт в картинке или PDF.
2. **Честность значений на уровне типа.** Тип `Tracked<T>` требует `confidence` и `source` — значение без источника не компилируется.
3. **Детерминизм.** Одинаковый вход → одинаковый StyleSpec. Достигается контент-адресуемым кэшем vision-этапа ([ADR-0003](docs/adr/0003-determinism.md)), а не параметрами модели — они на актуальных моделях Claude удалены.

## Структура

```
packages/core       Tracked<T>, статусы уверенности, единицы, ошибки, учёт себестоимости
packages/kb         справочники JSON + zod-схемы + загрузчик
packages/stylespec  схема StyleSpec, версионирование, миграции снапшотов
packages/vision     Claude API → VisionReport + контент-кэш
packages/assembly   POM · Construction · BOM · Labels · TechSequence — чистые функции
packages/flats      параметрический SVG-чертёж: перед, спинка и бок с объёмом
packages/docgen     StyleSpec → HTML → PDF, выгрузка по ролям, измерение вёрстки
packages/render     визуализация изделия из спеки — превью, вне технической геометрии
packages/pattern    раппорт из референсов: бесшовность проверяется пикселями
packages/library    библиотека артов бренда: рисунок переиспользуется между паками
packages/versions   версии техпака: снапшоты и дифф между ними
packages/i18n       словарь документа: русский, английский, китайский
packages/fit        сравнение факта со спекой: рулетка сейчас, примерки образцов потом
apps/cli            станок фазы 0
golden/             сценарии, инварианты, перебор пространства входов
```

Зависимости строго вниз: `core ← kb ← stylespec ← {vision, assembly} ← {flats, docgen} ← apps`.

## Категории

Трикотажное ядро: **футболка, лонгслив, свитшот, худи** — с принтом и без. Всё остальное получает честный отказ — документ вышел бы хуже, чем нужно фабрике.

## Разработка

```bash
pnpm install
pnpm verify        # формат + линт + типы + тесты — то же, что гоняет CI
pnpm golden        # голден-набор: сценарии, инварианты, перебор, вёрстка, станок
```

Полезное по отдельности:

```bash
pnpm kb:validate         # валидация справочников + бэклог верификации
pnpm stylespec:examples  # пересборка эталонных примеров спеки
pnpm flats:preview       # чертежи всех категорий в HTML
pnpm vision:analyze <фото> --category hoodie   # разбор фотографии, нужен ключ API

pnpm fit:form --category hoodie --out out/бланк.pdf   # печатный бланк замеров
pnpm fit:score                                        # сравнить документ с реальной вещью
pnpm fit:demo                                         # то же на синтетике, для показа

pnpm golden:export       # живые отчёты разбора из кэша в фикстуры
pnpm golden:renders      # референсные визуализации из кэша в golden/renders

pnpm pattern --refs мотив1.png мотив2.png --brief "что нарисовать" --save имя
pnpm library                                       # каталог артов бренда
pnpm fit:apply <бланк-замеров.json>                # примерка → новая версия
pnpm versions [артикул] [номер]                    # история и что изменилось
pnpm admin                                         # панель консьержа → out/admin.html
pnpm site --versions versions --out out/site       # ревью-сайт для фабрик и брендов
pnpm generate --answers <анкета> --lang en zh      # фабричные комплекты на трёх языках
pnpm fit:form --category hoodie --lang zh          # бланк замеров на языке того, кто мерит

pnpm rfq --answers анкета.json --out out/rfq.pdf   # лист на просчёт + текст в мессенджер
pnpm rfq:report --init rfq/responses.csv           # завести журнал ответов фабрик
pnpm rfq:report rfq/responses.csv                  # отчёт: ответили, берутся, цена
```

## Врёт ли документ в сантиметрах

Тесты этого не показывают — они говорят «документ внутренне непротиворечив».
Разница закрывается рулеткой: [docs/RULER-PROTOCOL.md](docs/RULER-PROTOCOL.md).

Метрика — не средняя ошибка в сантиметрах, а доля точек, попавших в допуск,
который документ сам же объявил. Так работает ОТК на фабрике.

## Сборка техпака

```bash
pnpm generate --answers golden/answers/tshirt-women-46.json \
              --photos front:перед.jpg back:спинка.jpg \
              --out out/pack.pdf \
              --roles qc technologist supply \
              --render \
              --spec
```

Ракурс кадра объявляется префиксом (`front:`, `back:`, `neck:`, `hem:`, `sleeve:`, `inside:`, `form:`) либо угадывается по имени файла. Он определяет, о чём спрашивать модель: точки спинки с кадра переда не читаются вообще, и без объявленного ракурса модель либо угадывает их, либо честно отказывается — второе лучше. Документ считает, какой недостающий кадр закроет больше всего предположений, и говорит это словами.

Фотографии необязательны: без них замеры берутся типовыми для категории и посадки, и документ честно это показывает. Ключ API нужен только для разбора фотографий — сборка спеки, чертёж и документ работают без него.

`--render` добавляет страницу «Внешний вид»: визуализацию изделия, собранную **из спеки**, и снимки заказчика рядом. Это платный внешний вызов, поэтому он только по флагу; кэш при этом читается всегда, и повторная сборка того же изделия картинку не оплачивает. Ни один размер документа с этой страницы не берётся — границы решения в [ADR-0005](docs/adr/0005-render-boundary.md).

## Откуда взяты числа

Размерные сетки — ГОСТ 31396-2009 и 31399-2009 (таблица 3 каждого), допуски — ГОСТ 23193-78, приращения градации — формулы ЕМКО СЭВ и немецкая школа. Тома-первоисточники лежат в [knowledge-base/etalon/](knowledge-base/etalon/), разбор решений — в [ADR-0006](docs/adr/0006-etalon-calibration.md).

Первоисточник вытесняет оценку только там, где он говорит о **той же самой** величине. Где не говорит — значение остаётся помеченным и ждёт рулетки.

## Справочники — это код

Файлы в `packages/kb/data/` версионируются в репо и меняются через PR с описанием причины: ошибка QA, фидбек фабрики, результат отшива. Так работает петля обучения продукта — без ML-тренинга.

Каждая запись несёт `verified` и `source`. Значение с `verified: false` **обязано** объяснять в поле `gap`, чего именно ему не хватает; значение с `verified: true` — в поле `note_ru`, чем именно оно подтверждено. Иначе справочник не грузится: флаг без объяснения нечем оспорить. Текущий бэклог верификации показывает `pnpm kb:validate`.

## Примеры-ловушки

`golden/traps.test.ts` — собрание случаев, где интуиция говорит одно, а измерение
другое: рамка по краю тайла ≠ шов, градиент ≠ кайма, плечи оверсайза ≠ шире груди.
Все пять поймали нас самих, когда мы писали тест к уже правильной метрике.

Набор существует для двух вещей. Он защищает метрику от «улучшения» под неверную
интуицию — увидев, что рамка не бракуется, легко решить, что порог занижен,
и починить работающее. И он учит: человек, пришедший в код после нас, за пять минут
узнаёт, где здесь тонко, вместо того чтобы наступить на всё заново.

Формат жёсткий: что подсказывает интуиция → что говорит измерение → почему право
измерение.

## Качество

Чему в этом коде можно верить и почему — [docs/QA-REPORT.md](docs/QA-REPORT.md). Там же список дефектов, которые мы нашли сами, и прямой перечень того, чего проверки НЕ доказывают.

Коротко: тесты говорят «документ внутренне непротиворечив и правдоподобен». Они не говорят «сантиметры верные» — это показывает только сравнение с рулеткой на реальных изделиях.

## Definition of Done

Код + тест + прогон голден-набора + обновлённый ADR или док + строка в [CHANGELOG.md](CHANGELOG.md).

## Бинарные файлы

Картинки, шрифты и PDF идут через **Git LFS** — правила в `.gitattributes`.
Один раз на машину:

```bash
brew install git-lfs && git lfs install
```

Без этого коммит бинарника упадёт с ошибкой внешнего фильтра. Уже
закоммиченные файлы остаются обычными блобами: перенос истории в LFS —
отдельное решение, оно переписывает историю.
