# SpecForm OS

Фото изделия → **StyleSpec** (структурированные данные изделия) → производственный техпак, который фабрика РФ принимает в работу. Каждое значение несёт статус уверенности.

> Рабочее имя. `SpecForm OS` занято конкурентом — переименование решается до публичного лендинга (D8 в [DEV-PLAN.md](DEV-PLAN.md)).

## Зачем это существует

Основатель малого бренда без технического бэкграунда получает от фабрики запрос «пришлите КД и лекала» и не знает этих слов. Фрилансер-конструктор берёт 3–10 тыс. ₽ и 1–2 недели на модель; цена ошибки — брак партии на 150–300 тыс. ₽ собственных денег.

Конкуренты генерируют **изображения** техпаков и говорят «доработайте сами». Мы генерируем **данные**, из которых документ рендерится: правка замера обновляет чертёж, узлы проверены под парк машин реального цеха, допуски и градация считаются автоматом.

**North Star:** доля техпаков, принятых фабрикой в работу без возврата на доработку.

## Три принципа, которые определяют весь код

1. **Данные первичны, изображения вторичны.** Всё — проекция StyleSpec. Правда никогда не живёт в картинке или PDF.
2. **Честность значений на уровне типа.** Тип `Tracked<T>` требует `confidence` и `source` — значение без источника не компилируется.
3. **Детерминизм.** Одинаковый вход → одинаковый StyleSpec. Достигается контент-адресуемым кэшем vision-этапа ([ADR-0003](docs/adr/0003-determinism.md)), а не параметрами модели — они на актуальных моделях Claude удалены.

## Структура

```
packages/core       Tracked<T>, статусы уверенности, единицы, ошибки, учёт себестоимости
packages/kb         справочники JSON + zod-схемы + загрузчик
packages/stylespec  схема StyleSpec, версионирование, миграции снапшотов
packages/vision     Claude API → VisionReport + контент-кэш
packages/assembly   POM · Construction · BOM · Labels · TechSequence — чистые функции
packages/flats      параметрический SVG-рендерер
packages/docgen     StyleSpec → HTML → PDF, экспорт по ролям
apps/cli            станок фазы 0
golden/             эталонные фото + ожидаемые StyleSpec + снапшоты
```

Зависимости строго вниз: `core ← kb ← stylespec ← {vision, assembly} ← {flats, docgen} ← apps`.

## Разработка

```bash
pnpm install
pnpm verify        # формат + линт + типы + тесты — то же, что гоняет CI
```

Отдельные команды:

```bash
pnpm test          # юнит-тесты
pnpm golden        # прогон голден-сета (гейтит мерж отдельно)
pnpm kb:validate   # валидация справочников + бэклог верификации
pnpm typecheck
```

## Справочники — это код

Файлы в `packages/kb/data/` версионируются в репо и меняются через PR с описанием причины: ошибка QA, фидбек фабрики, результат отшива. Так работает петля обучения продукта — без ML-тренинга.

Каждая запись несёт `verified` и `source`. Значение с `verified: false` **обязано** объяснять в поле `gap`, чего именно ему не хватает — иначе справочник не грузится. Текущий бэклог верификации показывает `pnpm kb:validate`.

## Definition of Done

Код + тест + прогон голден-сета + обновлённый ADR или док + строка в [CHANGELOG.md](CHANGELOG.md).
