# ADR-0003 — Детерминизм через контент-адресуемый кэш vision

**Статус:** принято · 2026-08-25 · заменяет требование «низкая temperature» в `TECH-REQUIREMENTS-PIPELINE.md` §6 и `CTO-SPEC.md` §1.2

## Контекст

Требование продукта: одинаковый вход → одинаковый `StyleSpec`, 100% (`PRD.md` §4). Урок конкурента: генеративная вариативность разрушает доверие к документу.

Спека закладывала достижение детерминизма через минимальную температуру модели. **Это больше не исполнимо:** на актуальных моделях Claude (Opus 5, Sonnet 5, Fable 5, Opus 4.7/4.8) параметры сэмплирования `temperature`, `top_p`, `top_k` удалены из API — запрос с ними возвращает 400.

## Решение

Детерминизм обеспечивается архитектурой, а не параметром модели.

**1. Пайплайн делится на два класса стадий.**

| Класс               | Стадии                  | Как достигается воспроизводимость                           |
| ------------------- | ----------------------- | ----------------------------------------------------------- |
| Недетерминированные | vision-анализ           | контент-адресуемый кэш (см. ниже)                           |
| Детерминированные   | assembly, flats, docgen | чистые функции без побочных состояний и без обращений к LLM |

**2. Ключ кэша:**

```
cache_key = sha256( photo_hashes[] ⊕ answers_hash ⊕ prompt_version ⊕ model_id ⊕ vision_schema_version )
```

Первый вызов на уникальный ключ идёт в API, результат сохраняется. Любой повтор возвращает тот же `VisionReport` — байт в байт. Отсюда идентичный `StyleSpec`.

**3. Смена промпта или модели меняет ключ.** Это не побочный эффект, а фича: дрейф точности становится явным событием с обязательным прогоном голден-сета, а не тихой деградацией между релизами.

**4. Побочная выгода:** бесплатный повтор генерации после ошибки рендера или сборки (`PRD.md` §6, «кредит только за успех») не тратит vision-токены — дорогая стадия уже в кэше.

**5. Чего кэш НЕ делает:** он не гарантирует _правильность_, только _повторяемость_. Правильность меряется голден-сетом против реальных замеров рулеткой. Две разные метрики, не путать.

## Последствия

- Кэш — часть контура данных: бэкапится, живёт в РФ-контуре, чистится по запросу на удаление данных пользователя.
- Инвалидация кэша при смене модели = разовый всплеск себестоимости. Планировать вместе с прогоном голден-сета.

## Когда пересматривать

Если Anthropic вернёт управление сэмплированием — кэш всё равно остаётся, он даёт экономию и явную точку контроля дрейфа.
