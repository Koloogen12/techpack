# Бланки замеров реальных изделий

Здесь лежат **настоящие** замеры отшитых образцов — по одному файлу на изделие.
Каталог сейчас пуст, и это правильно: синтетический «отшив» в голден-наборе —
ровно та ложь, против которой построен весь продукт. Первый файл появится
после первого реального обмера.

## Как сюда попадает файл

1. `pnpm fit:form --category hoodie --out out/бланк.pdf` — печатный бланк.
   Тому, кто мерит, нужен лист и рулетка, а не JSON. Язык бланка — `--lang ru|en|zh`.
2. Обмер по протоколу: `docs/RULER-PROTOCOL.md`.
3. Заполненный бланк переносится сюда файлом вида:

```json
{
  "id": "ОТШИВ-01",
  "photo": "golden/photos/hoodie-front.jpg",
  "answers": "golden/answers/hoodie-women-46.json",
  "measured_by": "кто мерил",
  "measured_at": "2026-08-26",
  "method": "flat_tape",
  "garment_note": "что это за вещь своими словами",
  "label_size": "M",
  "values": [
    { "code": "T01", "value_cm": 68.0 },
    { "code": "T03", "value_cm": 64.5, "repeat_cm": 64.0 }
  ]
}
```

## Что дальше делают с файлом

| Команда | Что делает |
| --- | --- |
| `pnpm fit:score` | сравнивает документ с рулеткой: доля точек в допуске, систематический снос, худшие промахи |
| `pnpm fit:apply <файл>` | применяет замеры к спеке — точки получают статус «подтверждено по образцу» и рождается новая версия |

## Требования к файлу, из-за которых он не примется

- **`method` обязателен.** `flat_tape` — эталон; `on_form` (на манекене) **не подтверждает
  табель вовсе**: табель описывает изделие разложенным, а на манекене вещь натянута.
- **`photo` обязателен.** Замеры без снимка того же изделия не калибруют ничего:
  нечем проверить, что мерили именно ту вещь, которую разбирал пайплайн.
- Два замера одной точки, расходящиеся больше чем на 2 см, файл не пройдёт:
  такое расхождение означает, что мерили по-разному, и эталоном такая пара быть не может.
